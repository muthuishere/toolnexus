import { Tabs, TabItem, Aside } from '@astrojs/starlight/components';

<Aside type="tip" title="Why you need this">
Before 0.22.0, a client with no `apiKey` took the first of `OPENROUTER_API_KEY`,
`OPENAI_API_KEY`, `ANTHROPIC_API_KEY` that was set and sent it to whatever `baseUrl` you
configured. With several keys in your environment, an OpenRouter key could go to
api.openai.com, or any key to a local or third-party server. Now a key only ever goes to the
host it belongs to.
</Aside>

<Aside type="caution" title="Breaking in 0.22.0">
A client on a **local or custom `baseUrl`** (Ollama, llama-server, vLLM, LM Studio, a company
proxy) that relied on the old fallback now fails to build. Set `apiKey` or `apiKeyEnv`.
</Aside>

## The rule, in order

1. `apiKey` is set: send it, and nothing else.
2. Else `apiKeyEnv` is set: read **that** env var (the variable's *name*, never its value, goes
   in your code).
3. Else read only the env var of the `baseUrl` host, over **https**:

   | host | env var |
   |---|---|
   | `api.openai.com` | `OPENAI_API_KEY` |
   | `api.anthropic.com` | `ANTHROPIC_API_KEY` |
   | `openrouter.ai` (and subdomains) | `OPENROUTER_API_KEY` |

4. Any other host, or plain `http`, without `apiKey` / `apiKeyEnv`: an error. There is no
   cross-provider fallback.

`listModels` follows the same rule.

## A local server and a proxy

<Tabs syncKey="lang">
<TabItem label="JavaScript">
```js
// local server that ignores the key: any placeholder
const local = createClient({ baseUrl: "http://localhost:11434/v1", style: "openai", model: "llama3", apiKey: "unused" })
// proxy: name the env var to read
const proxy = createClient({ baseUrl: "https://llm.internal/v1", style: "openai", model: "m", apiKeyEnv: "INTERNAL_LLM_KEY" })
```
</TabItem>
<TabItem label="Python">
```python

proxy = create_client(base_url="https://llm.internal/v1", style="openai", model="m", api_key_env="INTERNAL_LLM_KEY")
```
</TabItem>

A hosted provider needs neither: `baseUrl: "https://openrouter.ai/api/v1"` with
`OPENROUTER_API_KEY` in the environment works as before.
