<Aside type="tip" title="Why you need this">
If you already use the Grok, Codex or Google Antigravity CLI, toolnexus can drive that official CLI
in its documented headless mode (`grok -p`, `codex exec`, `agy -p`), signed in by you, on your
machine. It picks up the file the CLI saved and hands it back to your code or your agent, with the
same `generateMedia` / `createMedia` API as every other media style.

Your provider's terms of service apply to how you use its CLI.
</Aside>

Contract: SPEC §7G.10, §7G.10a, §7G.10b · ADR 0042 · `conformance/media/cli.json`.

## The three presets

| preset (shell `--style`) | CLI | verbs | logged-in check | headless flags |
|---|---|---|---|---|
| `xai-grok-cli` | `grok` | image, video | `~/.grok/auth.json` exists | `-p … --output-format streaming-json --yolo --no-auto-update` |
| `openai-codex-cli` | `codex` | image | `$CODEX_HOME/auth.json` (default `~/.codex/auth.json`) exists | `exec --json --skip-git-repo-check -s workspace-write` |
| `google-agy-cli` | `agy` | image | `~/.gemini/antigravity-cli/antigravity-oauth-token` exists | `-p … --output-format stream-json --dangerously-skip-permissions` |

Each language spells the constants its own way (see the tabs below); they are plain strings underneath.

## Install and log in

Toolnexus never installs, logs in or changes settings for you. Check each CLI works by hand once:

- **Grok** — `grok login` signs in (`grok --oauth` forces the browser login). `grok usage`
  prints your plan's usage limit.
- **Codex** — `codex login`, then `codex login status` should print `Logged in using ChatGPT`.
- **Antigravity** — run `agy` and sign in when it asks; `agy models` lists the models you can use.

Then check from code, in a few milliseconds and without generating anything, with
`available()` on the loaded style (examples under [Errors](#errors)). It checks that the command is
on `PATH` and that the CLI's own login file exists, and never reads the file.

### From the shell

```sh
toolnexus media image --style xai-grok-cli     --prompt "a red apple" --aspect-ratio 16:9 --out ./out
toolnexus media video --style xai-grok-cli     --prompt "waves on a beach"
toolnexus media image --style openai-codex-cli --prompt "a red apple" --name apple
toolnexus media image --style google-agy-cli   --prompt "a red apple" --model <model>
```

It prints the path of each saved file, one per line, and exits non-zero with the error on stderr
(`error: media: no style supports "video"` for `toolnexus media video --style openai-codex-cli`).
Flags: `--style`, `--prompt`, `--aspect-ratio`, `--width`, `--height`, `--seconds`, `--model`,
`--out`, `--name`, `--timeout-ms`. `--style` also takes the path of an HTTP style JSON file.

## 2. Use it as a function (agent tool)

Pass the media object to the toolkit and your agent gets one tool per verb the preset declares:
`generate_image` for all three, plus `generate_video` for Grok. Any LLM can call it. Every file
the agent makes lands in `RunResult.files`, in call order. Only images go back to the model; a
video reaches it only as a `video ready: <path>` line.

## 3. Errors

A direct call fails with a typed media error whose status is `failed`, `timeout`, `cancelled`
or `unavailable`. `unavailable` means the call was valid but the CLI cannot serve it right now:
not installed, not logged in, usage limit reached, or Grok video blocked by Zero Data Retention.
Check `available()` first if you want to skip a CLI without starting it.

<Tabs syncKey="lang">
<TabItem label="JavaScript">
```ts
import { createMedia, loadMediaStyle, MediaStyle, MediaUnavailableError } from "toolnexus"

try {
  const r = await createMedia(style).video({ prompt: "waves on a beach", seconds: 6 })
```

### Error messages

The messages are the same in every language.

| when | status | message |
|---|---|---|
| verb the preset does not declare (e.g. `video` on Codex or Antigravity) | `failed` | `media: no style supports "video"` (no process starts) |
| an argument a CLI cannot express | `failed` | `image: argument "seed" not supported` |
| CLI not on `PATH` | `unavailable` | `grok: "grok" not found on PATH` |
| not logged in | `unavailable` | `codex: installed, not logged in (/Users/you/.codex/auth.json missing)` |
| usage limit reached | `unavailable` | `grok: You have reached your usage limit for today` · `codex: You've hit your usage limit. Try again later.` · agy: anything mentioning `quota` |
| Grok video under Zero Data Retention | `unavailable` | `grok: video blocked by Zero Data Retention — run /privacy and opt in, …` |
| run took too long | `timeout` | `grok: timed out after 600000ms` (the process is killed) |

From the shell, `toolnexus media` prints the message on stderr as `error: <message>` and exits non-zero.

## Size hints become prompt text

A CLI has no `--aspect-ratio` flag, so `width`, `height`, `seconds` and `aspectRatio` are appended
to your prompt, in that order, inside the preset's fixed instruction:

```
{prompt: "a red apple", width: 1024, aspectRatio: "16:9"}
  ⇒ Generate exactly one image with your image generation tool: a red apple (width 1024 px, aspect ratio 16:9). Do not write code. Reply only with the file path.
```

The model usually honours it (live, all three returned 16:9: Grok 1280×720, Codex 1672×941,
Antigravity 1376×768) but it is a request, not a guarantee. `seed` cannot be expressed this way
and is refused: `argument "seed" not supported`.

## Grok video

Toolnexus starts `grok` with `GROK_CONFIG={"features":{"image_gen":true,"video_gen":true}}` so the
image and video tools are switched on for that run. It never edits your Grok settings.

Grok's video tool obeys your account's **coding-data setting**. Under **Zero Data Retention** it
refuses, and you get:

```
grok: video blocked by Zero Data Retention — run /privacy and opt in, or configure ZDR video storage (docs/media#grok-video-zdr)
```

To fix it: run `grok`, type `/privacy` (Settings › Coding data, retention, and training), choose
**Opt in**, restart `grok`. Opting in means xAI may retain and train on your CLI coding data;
decide whether that is acceptable. xAI also documents a ZDR video bucket
(`[tools.zdr_video_output_s3]` in `~/.grok/managed_config.toml`); it did not work for us on a
personal account ([details](/toolnexus/media/#grok-video-zdr)). Live after opting in: one video in 58 s.

**Video length.** Pass `seconds` and it is folded into the prompt like the other size hints:
`{ prompt: "waves", seconds: 6 }` asks Grok for
`Generate exactly one video with your video generation tool: waves (about 6 seconds long). Do not write code. Reply only with the file path.`
Without `seconds` the prompt carries no duration phrase and Grok picks its own default length.
(0.29.0 asked for the "shortest duration available", which gave clips of about one second.)
The CLI flag is `toolnexus media video --style xai-grok-cli --seconds 6`.

## Usage limits and quota

Each CLI uses your plan's allowance. When it runs out the error status is `unavailable`:

- Grok: `grok: You have reached your usage limit for today` (check with `grok usage`).
- Codex: `codex: You've hit your usage limit. Try again later.`
- Antigravity: anything mentioning `quota` (Antigravity names its allowance the "Antigravity Starter Quota").
  Live, agy ends the turn normally and explains it (`429 RESOURCE_EXHAUSTED … quota will reset
  after approximately 167 hours`) with no file; the preset reports that as `unavailable`.

## The Grok watermark

Every Grok image we generated carries a small **"Grok" mark in the bottom-right corner**. Toolnexus
documents it and does not remove it. If you need clean images, use Codex or Antigravity.

## Models, timeouts, where files go

Pass a config to `loadMediaStyle(preset, config)` / `generateMedia(preset, verb, args, config)`:

- `model` (or `models: { image, video }`) — Grok and Codex get `-m <model>`, Antigravity
  `--model <model>`. List them with `grok models` or `agy models`. Unset means the CLI's default.
- `loop.timeoutMs` — default 600000 (10 min). On timeout the CLI process is killed:
  `grok: timed out after 600000ms`.
- `gather.dir` — where files are saved (default `<tmp>/toolnexus-media`).
  `gather.name: "cover"` names them `cover.jpg`, then `cover-2.jpg`, … (anything outside
  `A-Z a-z 0-9 . _ -` becomes `-`). `gather.mode: "url"` returns the CLI's own file path instead
  of a copy; `gather.keep: false` deletes the CLI's original after copying.
- `command` — the argv prefix, if the CLI is not on `PATH` as `grok` / `codex` / `agy`.

Every CLI runs in a fresh temporary working directory, with stdin closed.

Results say who served them: `result.style` is the preset id (`xai-grok-cli`), `result.model`
the model you configured (absent when you set none). `usage` appears only when the CLI reports it
(Grok's end event gives tokens and cost; Antigravity gives tokens); a price is never estimated.

## Permissions

Each preset runs headless and never stops for a prompt: Grok with `--yolo`, Antigravity with
`--dangerously-skip-permissions`, Codex with `exec -s workspace-write`. Codex stays sandboxed
because writing into its own workspace is enough to save the image.
