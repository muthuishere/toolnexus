```elixir
@spec memory_tool(String.t()) :: Toolnexus.Tool.t()
def memory_tool(dir)

# input_schema: {action: "add" | "replace" | "remove", target?: "self" | "user", text, with?}
# action=add   → appends "- <text>" to the target file
# action=replace → swaps an existing `text` substring for `with` (isError if absent)
# action=remove  → deletes an existing `text` substring (isError if absent)
# target=self (default) → MEMORY.md; target=user → USER.md
```

One tool, three actions, over two files under `dir`: `MEMORY.md` (the agent's own durable notes)
and `USER.md` (its model of the user). Every write lands on **disk** immediately; the current
session's prompt is not touched — the frozen soul snapshot picks it up at the start of the
**next** session. A `replace`/`remove` whose target substring is not found in the file is a loud
`is_error: true`, never a silent no-op.

## When to use it

- **You're building a persona that should remember things** — this is the builtin
  [`Toolnexus.Agents.Home.from_dir/2`](/api/elixir/persona/from-dir/) wires in by default; call
  `memory_tool/1` directly only when you want it standalone (a custom agent definition, a test,
  a tool list you're assembling by hand).
- **You want the model's mental model of the user tracked separately from its own notes** —
  `target: "user"` writes `USER.md` instead of `MEMORY.md`.

## Why this and not the alternative

<Aside type="tip" title="Reach for from_dir/2 for the everyday path">
`memory_tool/1` is the file-backed builtin itself. In application code you almost always want
[`Toolnexus.Agents.Home.from_dir/2`](/api/elixir/persona/from-dir/), which wires this tool over
the same directory it composed the soul from — pass `memory: false` there to opt back out. Call
`memory_tool/1` directly when you're assembling a toolkit by hand, or writing a test against the
tool in isolation.
</Aside>

## Examples

### 1. The smallest useful call — `add`, executed directly

```elixir test
alias Toolnexus.{Context, ToolResult}
alias Toolnexus.Agents.Home

dir = Path.join(System.tmp_dir!(), "toolnexus_doc_memory_tool_1_#{System.unique_integer([:positive])}")
File.rm_rf!(dir)
File.mkdir_p!(dir)

tool = Home.memory_tool(dir)
true = tool.name == "memory"

result = tool.execute.(%{"action" => "add", "text" => "prefers dark mode"}, %Context{})

%ToolResult{is_error: false} = result
true = String.contains?(result.output, "MEMORY.md")
true = File.read!(Path.join(dir, "MEMORY.md")) == "- prefers dark mode\n"

IO.puts("ok: #{result.output}")
```

### 2. The realistic case — `replace` and `remove`, and the loud miss

```elixir test
alias Toolnexus.{Context, ToolResult}
alias Toolnexus.Agents.Home

dir = Path.join(System.tmp_dir!(), "toolnexus_doc_memory_tool_2_#{System.unique_integer([:positive])}")
File.rm_rf!(dir)
File.mkdir_p!(dir)
File.write!(Path.join(dir, "MEMORY.md"), "- prefers dark mode\n- likes verbose logs\n")

tool = Home.memory_tool(dir)

replaced = tool.execute.(%{"action" => "replace", "text" => "verbose logs", "with" => "terse logs"}, %Context{})
false = replaced.is_error
true = File.read!(Path.join(dir, "MEMORY.md")) =~ "terse logs"

removed = tool.execute.(%{"action" => "remove", "text" => "- prefers dark mode\n"}, %Context{})
false = removed.is_error
false = File.read!(Path.join(dir, "MEMORY.md")) =~ "dark mode"

# a replace/remove target that isn't present is a loud error, not a silent no-op
miss = tool.execute.(%{"action" => "replace", "text" => "nonexistent", "with" => "x"}, %Context{})
true = miss.is_error
true = String.contains?(miss.output, "not found")

IO.puts("ok: replace + remove applied; miss reported as isError")
```

### 3. The full surface — `target: "user"` writes `USER.md` instead

```elixir test
alias Toolnexus.{Context, ToolResult}
alias Toolnexus.Agents.Home

dir = Path.join(System.tmp_dir!(), "toolnexus_doc_memory_tool_3_#{System.unique_integer([:positive])}")
File.rm_rf!(dir)
File.mkdir_p!(dir)

tool = Home.memory_tool(dir)

self_note = tool.execute.(%{"action" => "add", "text" => "checked the invoice twice"}, %Context{})
user_note = tool.execute.(%{"action" => "add", "target" => "user", "text" => "works in UTC+5:30"}, %Context{})

false = self_note.is_error
false = user_note.is_error
true = String.contains?(self_note.output, "MEMORY.md")
true = String.contains?(user_note.output, "USER.md")

true = File.read!(Path.join(dir, "MEMORY.md")) =~ "checked the invoice twice"
true = File.read!(Path.join(dir, "USER.md")) =~ "works in UTC+5:30"
# writes are on disk only — they say so, so a caller never assumes the live prompt changed
true = String.contains?(user_note.output, "loads next session")

IO.puts("ok: self note → MEMORY.md, user note → USER.md")
```

## Input schema

| Field | Type | Required | What it is |
|---|---|---|---|
| `action` | `"add" \| "replace" \| "remove"` | yes | The operation. |
| `target` | `"self" \| "user"` | no (default `"self"`) | `self` → `MEMORY.md`, `user` → `USER.md`. |
| `text` | `String.t()` | yes | For `add`: the entry. For `replace`/`remove`: the existing substring. |
| `with` | `String.t()` | for `replace` | The replacement text. |

## The notes tier — `notes`

```elixir
def memory_tool(dir, opts \\ [])   # notes: true
Home.from_dir(dir, notes: true, memory_index_cap: true | %{max_lines: 200, max_bytes: 25600})
```

Turn on `notes` (off by default) and the same `memory` tool grows a second tier. `MEMORY.md`
stays a **short index** loaded every session; the detail lives in **notes** at
`<dir>/memory/<slug>.md`, which are **never** injected into the prompt and are read only on
demand. With `notes` off, the tool's schema, description and behaviour are exactly as above.

| Addition | What it does |
|---|---|
| `target: "note:<slug>"` | `add` / `replace` / `remove` on `memory/<slug>.md`. `add` to a missing note creates it (and `memory/`). |
| `action: "read"` | Returns a file's content (`target` required: `self`, `user`, or a note). A missing note is an error. |
| `action: "list"` | One line per note, `<slug>\t<bytes>`, sorted by slug; `(no notes)` when empty. |

A slug matches `^[a-z0-9][a-z0-9._-]{0,63}$` and may not contain `..`; anything else is an
error before any file is touched. `replace` and `remove` change only the **first** occurrence of
the text, in every target. Writes are atomic (temp file, then rename), and writes to the same
file in one process are serialised, so parallel `add`s never lose an entry. Two processes
writing the same file: the last write wins.

```elixir
alias Toolnexus.Context
alias Toolnexus.Agents.Home

memory = Home.memory_tool("./personas/ava", notes: true)

memory.execute.(%{"action" => "add", "target" => "note:travel", "text" => "prefers aisle seats"}, %Context{})
memory.execute.(%{"action" => "add", "text" => "travel prefs: see [[travel]]"}, %Context{})   # the index line

IO.puts(memory.execute.(%{"action" => "list"}, %Context{}).output)                           # travel\t22
IO.puts(memory.execute.(%{"action" => "read", "target" => "note:travel"}, %Context{}).output)  # - prefers aisle seats
```

The **2 MB cap** only limits what goes into the prompt. Writes always read and rewrite the
whole file, so a `MEMORY.md` over 2 MB is never cut short on disk. The separate
`memoryIndexCap` option on [`fromDir`](/api/elixir/persona/from-dir/) caps the injected index
to whole lines (`true` = 200 lines / 25600 bytes) and adds a notice telling the model to move
detail into notes.
