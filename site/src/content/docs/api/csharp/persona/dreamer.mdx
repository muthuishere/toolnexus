`Home.Dreamer` builds the **dreamer**: a plain agent whose job is to keep a persona's memory true. Its
tools are **exactly** two — `memory` (with the notes tier on, over `dir`) and
[`transcript_search`](/api/csharp/persona/transcript-search-tool/) (over your conversation
store) — never the persona's shell or file tools. Its soul is one `## HEARTBEAT.md` section:
the SPEC constant `DREAM_PROMPT`, then `DREAM.md` from the home dir (if present), then
`instructions` (if given). Construction fails without a store, or with a store that cannot
`list()`.

Each pass works in order: **verify** every index line and note against the transcripts (fix
what they contradict, drop what they no longer support) → **demote** detail out of `MEMORY.md`
into a note behind a `[[slug]]` pointer → **merge** duplicate notes → **repair links** → **log**
one `dream: …` entry to `memory/log.md`. A pass with nothing to change writes nothing and replies
`HEARTBEAT_OK`, which the heartbeat keeps silent.

## When to use it

Use it for a long-lived persona whose memory is **written by the model** across many sessions:
a personal assistant, a support agent, an on-call operator. Those memories drift — a wrong fact
gets recorded once and then re-read every session. The dreamer fixes that offline, against the
transcripts, so the agent's memory gets better while it sleeps, not worse.

Skip it for one-shot workers, for memory a human curates by hand, or when you keep no
transcripts (there is nothing to verify against). See the [Dreaming guide](/toolnexus/dreaming/)
for the full when-to-use table and cadence advice.

## Why this and not the alternative

<Aside type="tip" title="Most of the time, use the dream option on Home.FromDir">
The one-line form — `Home.FromDir(dir, dream: everyMs + store)` — builds this dreamer and runs it
on the persona's own runtime when you start the persona with `Home.StartAgent`. Call `Home.Dreamer` directly
only when **you** own the schedule: a cron job, a CI step, a button, or a test that runs exactly
one pass.
</Aside>

A hand-written `HEARTBEAT.md` consolidator (the earlier recipe) can only tidy what memory
already says. It cannot tell a true note from a wrong one. The dreamer checks claims against the
transcripts, which are the ground truth, and records every change in `memory/log.md`, so a bad
"tidy" can be seen and reverted.

## Examples

### 1. The smallest useful call — dream nightly, one line

```csharp
using Toolnexus;
using Toolnexus.Agents;

var store = new FileConversationStore("./data/conversations");   // your client's transcripts

var ava = Home.FromDir("./personas/ava", new Home.FromDirOptions
{
    Notes = true,
    MemoryIndexCap = Home.MemoryIndexCapPreset,
    Dream = new Home.DreamOptions { EveryMs = 24 * 60 * 60_000, Store = store },   // dream nightly
});
var started = Home.StartAgent(ava, rtOpts, everyMs: 30 * 60_000);
// ... the dreamer runs on the same runtime; await started.StopAsync() stops both
```

### 2. The realistic case — your own schedule

```csharp
var d = Home.Dreamer("./personas/ava", new Home.DreamerOptions
{
    Store = new FileConversationStore("./data/conversations"),
});   // a plain Agent

// Your schedule: a 6-hourly heartbeat with its own onBeat.
var started = Home.StartAgent(d, rtOpts, everyMs: 6 * 60 * 60_000,
    onBeat: summary => Console.WriteLine($"dreamt: {summary}"));
```

### 3. The full surface — goal-focused prose and a single pass on demand

```csharp
var d = Home.Dreamer("./personas/ava", new Home.DreamerOptions
{
    Store = new FileConversationStore("./data/conversations"),
    Instructions = "Pay special attention to the user's travel preferences.",   // after DREAM.md
    Model = "openai/gpt-4o-mini",
});

// One pass, now — from a CI job, a button, or a test.
var r = await d.RunAsync(rtOpts, Home.HeartbeatPrompt);
Console.WriteLine(r.Text);   // "HEARTBEAT_OK" when memory already matched the transcripts
```

Put standing guidance in `DREAM.md` in the home dir (it is read when the dreamer is built);
use `instructions` for guidance that depends on the host.

## Options

| Option | Default | What it does |
|---|---|---|
| store | — (required) | The conversation store to verify against. It must support `list()`. |
| instructions | none | Host prose appended after `DREAM_PROMPT` and `DREAM.md`. |
| name | `<basename(dir)>-dreamer` | The agent's name. |
| model | `inherit` | Model id. `inherit` uses the runtime's model; a cheaper model is usually enough. |

On `Home.FromDir`, the `dream` option takes `everyMs` (must be > 0), `store`, and optional
`instructions`. Leaving it out changes nothing.
