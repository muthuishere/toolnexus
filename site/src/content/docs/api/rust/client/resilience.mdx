```rust
pub struct ErrorInfo { pub error: String, pub status: u16, pub attempt: u32, pub retryable: bool }
pub enum ErrorTier { Retry, Fail }
pub type OnErrorFn = Arc<dyn Fn(&ErrorInfo) -> ErrorTier + Send + Sync>;
```

Classify an LLM error into retry / fail, bound a run with a deadline, and cancel cleanly.

## When to use it

To decide, per failed LLM attempt, whether to retry or fail — `on_error` sees the status, attempt number and the default classification. Retries also honour `Retry-After`.

## Why this and not the alternative

Use `on_error` over wrapping `run` in your own retry loop: the loop's retries keep the transcript and never retry a cancellation.

<Aside type="tip" title="When not to use it">
For simple tuning, `retries`, `retry_base_ms` and `retryable_statuses` are enough.
</Aside>

## Examples

### 1. Fail fast

```rust
use std::sync::Arc;
use toolnexus::client::{ClientOptions, ErrorTier, create_client};
let client = create_client(ClientOptions { on_error: Some(Arc::new(|_| ErrorTier::Fail)), ..Default::default() });
```

### 2. Retry a provider-specific status

```rust
use toolnexus::client::{ClientOptions, create_client};
let client = create_client(ClientOptions { retries: 5, retry_base_ms: 250, retryable_statuses: vec![408], ..Default::default() });
```

### 3. Never retry auth failures

```rust
use std::sync::Arc;
use toolnexus::client::{ClientOptions, ErrorTier, create_client};
let client = create_client(ClientOptions {
    on_error: Some(Arc::new(|e| if e.status == 401 || e.status == 403 { ErrorTier::Fail } else if e.retryable { ErrorTier::Retry } else { ErrorTier::Fail })),
    ..Default::default()
});
```
