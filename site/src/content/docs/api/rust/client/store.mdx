Swap in-memory history for your own store so a conversation survives a process restart.

## When to use it

Behind `ask(prompt, tk, id)`: where transcripts are kept by id. In-memory is the default; the file store writes each conversation atomically so it survives a restart.

## Why this and not the alternative

Use a store over a `Conversation` when several requests (or processes) continue the same id.

<Aside type="tip" title="When not to use it">
Implement `ConversationStore` yourself for a database; do not reach into the file store's layout.
</Aside>

## Examples

### 1. The default

```rust
use toolnexus::client::{ClientOptions, Style, create_client};
use toolnexus::{ToolkitOptions, create_toolkit};
let tk = create_toolkit(ToolkitOptions::default()).await?;
let client = create_client(ClientOptions {
    base_url: "https://openrouter.ai/api/v1".into(),
    style: Style::OpenAI,
    model: "openai/gpt-4o-mini".into(),
    ..Default::default()
});
client.ask("I like tea", &tk, "u1").await?;
let r = client.ask("What do I like?", &tk, "u1").await?;
```

### 2. Persist to disk

```rust
use std::sync::Arc;
use toolnexus::client::{ClientOptions, create_client};
use toolnexus::store::FileConversationStore;
let store = Arc::new(FileConversationStore::new("/var/lib/myapp/conversations")?);
let client = create_client(ClientOptions { store: Some(store), ..Default::default() });
```

### 3. Your own store

```rust
use serde_json::Value;
use toolnexus::store::ConversationStore;
struct Db;
impl ConversationStore for Db {
    fn get(&self, _id: &str) -> Result<Option<Vec<Value>>, String> { Ok(None) }
    fn save(&self, _id: &str, _m: &[Value]) -> Result<(), String> { Ok(()) }
}
```
