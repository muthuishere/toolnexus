```rust
pub fn parse_agents_config(block: &AgentsConfig) -> Vec<Agent>
pub fn parse_agents_value(v: &Value) -> Vec<Agent>
pub type AgentsConfig = BTreeMap<String, AgentConfig>;  // {card, headers, timeout, pollEvery, enabled, disabled}
```

Turn an `agents` config block into `Agent`s, with the same precedence as MCP servers:
`disabled: true` wins, then `enabled: false`; an entry without a `card` is skipped. The key is only
an identifier: the tool prefix comes from the card's `name`.

## When to use it

When the peers live in config next to `mcpServers`. `create_toolkit` already reads a top-level
`agents` block from `mcp_config` (file or JSON), so you only call this to inspect the block yourself.

## Why this and not the alternative

Declaring agents in config keeps URLs and `${ENV}` header references out of code, and the
`enabled` / `disabled` switches mean the same thing they do for MCP servers.

## Examples

### 1. The block create_toolkit reads

```rust
use serde_json::json;
use toolnexus::{McpConfigInput, ToolkitOptions, create_toolkit};
let tk = create_toolkit(ToolkitOptions {
    mcp_config: Some(McpConfigInput::Json(json!({
        "agents": {"rev": {"card": "https://reviewer.example/.well-known/agent-card.json", "pollEvery": 500}}
    }))),
    ..Default::default()
}).await?;
```

### 2. Precedence

```rust
use serde_json::json;
use toolnexus::a2a::parse_agents_value;
let agents = parse_agents_value(&json!({
    "a": {"card": "http://x/1"},
    "b": {"card": "http://x/2", "disabled": true},
    "c": {"card": "http://x/3", "enabled": false},
    "d": {"card": "http://x/4", "enabled": true, "disabled": true},
}));
assert_eq!(agents.len(), 1);   // only "a"
```

### 3. Typed entries

```rust
use std::collections::BTreeMap;
use toolnexus::a2a::{AgentConfig, parse_agents_config};
let agents = parse_agents_config(&BTreeMap::from([(
    "rev".to_string(),
    AgentConfig { card: "http://x/1".into(), timeout: 60_000, ..Default::default() },
)]));
```
