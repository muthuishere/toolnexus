A relay tool carries a schema and no behaviour: when the model calls it, the run suspends with a
`kind: "tool_call"` Request carrying the call (`data.calls`, with the provider's call id stamped in),
and the HOST executes it. Every relay call of one assistant turn rides the one surfaced Request, in
tool-call order. With a `wait_for`, the host's `data.output` (and `data.isError`) becomes the tool
result inline. Without one the run halts `pending`; `run_with_answer` resumes it from the persisted
transcript, replacing the halt's placeholders so every call has exactly one result, and appends no
new user turn. The answer must echo the request id. A relay tool may not share a name with a
builtin, even with builtins off (`ToolkitError::Relay`).

## Example

```rust
use toolnexus::relay::{RelayResult, relay_answer, relay_calls_of, relay_tool};
let tk = toolnexus::create_toolkit(toolnexus::ToolkitOptions {
    builtins: Some(toolnexus::BuiltinsConfig::off()),
    extra_tools: vec![relay_tool("lookup", "look something up", None)],
    ..Default::default()
}).await?;
let halted = client.run("weather?", &tk).await?;                 // status == "pending"
let req = halted.pending.clone().unwrap();
let results: Vec<RelayResult> = relay_calls_of(&req).into_iter()
    .map(|c| RelayResult { id: c.id, output: "sunny".into(), is_error: false }).collect();
let done = client.run_with_answer(Default::default(), &tk, halted.messages, &req, &relay_answer(&req.id, &results)).await?;
```
