Turn an HTTP endpoint into a tool: URL, method, headers with $\{ENV\} expansion, and a schema.

## When to use it

To expose a REST endpoint as a tool with no code: `\{placeholder\}` URL segments come from the arguments, the rest become query params (GET) or a JSON/form/raw body, and `$\{ENV\}` header values are expanded at call time and never logged.

## Why this and not the alternative

Use this over a native tool wrapping reqwest when the call is a straight request/response; you get the §7 error shape (`HTTP <status>: <body>`) for free.

<Aside type="tip" title="When not to use it">
When the call needs logic around it (pagination, auth refresh), write a `define_tool` instead.
</Aside>

## Examples

### 1. GET with placeholders

```rust
use toolnexus::http::{HttpToolOptions, http_tool};
let t = http_tool(HttpToolOptions {
    name: "repo".into(), description: "GitHub repo".into(),
    url: "https://api.github.com/repos/{owner}/{repo}".into(),
    headers: [("User-Agent".to_string(), "me".to_string())].into(),
    ..Default::default()
});
```

### 2. POST JSON with a secret header

```rust
use toolnexus::http::{HttpToolOptions, http_tool};
let t = http_tool(HttpToolOptions {
    name: "create_issue".into(), description: "Open an issue".into(), method: "POST".into(),
    url: "https://api.example.com/issues".into(),
    headers: [("Authorization".to_string(), "Bearer ${EXAMPLE_TOKEN}".to_string())].into(),
    ..Default::default()
});
```

### 3. Status-prefixed results

```rust
use toolnexus::http::{HttpToolOptions, http_tool};
let t = http_tool(HttpToolOptions {
    name: "health".into(), description: "Health".into(),
    url: "https://example.com/health".into(), result_mode: "status+text".into(), timeout: 5000,
    ..Default::default()
});
```
