The non-text half of a message: text | image | file | audio, carrying base64 bytes or a URL plus a mimeType — never a path.

## When to use it

When a tool returns non-text content — an image the `read` builtin loaded, a screenshot, an MCP image result — put it in `ToolResult.parts`; the client relocates it into the provider's shape (§8A).

## Why this and not the alternative

Use parts rather than base64 inside `output`: text output is token-counted and unreadable to a vision model, while a part reaches the model as an image block.

<Aside type="tip" title="When not to use it">
Never put a filesystem path in a part (§0 1b): carry `data` or `url`, exactly one.
</Aside>

## Examples

### 1. An image part

```rust
use toolnexus::{ContentPart, ToolResult};
let png_b64 = String::from("iVBORw0KGgo="); // your bytes, base64
let mut r = ToolResult::ok("screenshot.png (image/png)");
r.parts.push(ContentPart { kind: "image".into(), mime_type: "image/png".into(), data: png_b64, ..Default::default() });
```

### 2. A file by URL

```rust
use toolnexus::ContentPart;
let p = ContentPart { kind: "file".into(), mime_type: "application/pdf".into(), url: "https://example.com/a.pdf".into(), ..Default::default() };
```

### 3. Check a part before sending

```rust
use toolnexus::ContentPart;
use toolnexus::client::validate_part;
let p = ContentPart { kind: "image".into(), mime_type: "image/png".into(), ..Default::default() };
assert!(validate_part(&p, 0).is_err()); // neither data nor url
```
