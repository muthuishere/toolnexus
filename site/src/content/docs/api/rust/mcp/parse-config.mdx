Parse and validate config without connecting — the fast fail for a malformed or misspelled server block.

## When to use it

To validate or inspect an MCP config before connecting: it accepts `mcpServers` | `servers` | `mcp`, command strings or arrays, `enabled` / `disabled`, timeouts and the per-server `tools` allowlist.

## Why this and not the alternative

Parse once and keep the typed `McpConfig` (`McpConfigInput::Parsed`) when you build several toolkits from the same file.

<Aside type="tip" title="When not to use it">
`create_toolkit` with `McpConfigInput::Path` parses for you; call this directly only when you need the typed config.
</Aside>

## Examples

### 1. From JSON

```rust
use serde_json::json;
use toolnexus::mcp::parse_mcp_config;
let cfg = parse_mcp_config(&json!({"mcpServers": {"fs": {"command": ["npx", "-y", "server-fs"]}}}))?;
assert!(!cfg["fs"].is_remote());
```

### 2. A remote server with env headers

```rust
use toolnexus::mcp::parse_mcp_config_str;
let cfg = parse_mcp_config_str(r#"{"servers":{"api":{"url":"https://example.com/mcp","headers":{"Authorization":"Bearer ${API_TOKEN}"}}}}"#)?;
assert!(cfg["api"].is_remote());
```

### 3. Feed a toolkit

```rust
use toolnexus::mcp::parse_mcp_config_file;
use toolnexus::{McpConfigInput, ToolkitOptions, create_toolkit};
let cfg = parse_mcp_config_file("mcp.json")?;
let tk = create_toolkit(ToolkitOptions { mcp_config: Some(McpConfigInput::Parsed(cfg)), ..Default::default() }).await?;
```
