// enable it: ToolkitOptions { wait_for: Some(..), .. }  (or McpLoadOptions { wait_for, .. })

When the toolkit is built with a `wait_for`, every MCP client advertises the `elicitation`
capability and answers `elicitation/create` through it — inline, without re-executing the tool.
Form mode becomes `kind: "input"` with the requested schema in `data.schema`; URL mode becomes
`kind: "authorization"` with `url`. The Answer maps back: `ok` → `accept` (content = `answer.data`,
or `{}`), `reason: "declined"` → `decline`, anything else → `cancel`. Without a `wait_for` the
capability is not advertised, so a compliant server never elicits.

## Example

```rust
use std::sync::Arc;
use toolnexus::{Answer, McpConfigInput, ToolkitOptions, create_toolkit};
let ask: toolnexus::client::WaitForFn = Arc::new(|req| Box::pin(async move {
    // show req.prompt (and req.data["schema"] / req.url) to the user
    Ok(Answer { id: req.id, ok: true, data: None, ..Default::default() })
}));
let tk = create_toolkit(ToolkitOptions {
    mcp_config: Some(McpConfigInput::Path("mcp.json".into())),
    wait_for: Some(ask.clone()),   // typically the same function given to the client
    ..Default::default()
}).await?;
```
