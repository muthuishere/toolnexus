The ctx-aware load: bound connection time and cancel a slow or hung server without leaking a child process.

## When to use it

When one slow server must not hold up the others: `on_server` fires the moment each server is connected, failed or disabled, so you can `register` its tools into a live toolkit.

## Why this and not the alternative

Use this over `load_mcp` when start-up latency matters; the returned source is the same once every server has finished.

<Aside type="tip" title="When not to use it">
Cancellation of the whole load is not a parameter in Rust; wrap the call in `tokio::time::timeout` if you need a deadline.
</Aside>

## Examples

### 1. Log readiness

```rust
use std::sync::Arc;
use toolnexus::mcp::{McpLoadOptions, load_mcp_with, parse_mcp_config_file};
let cfg = parse_mcp_config_file("mcp.json")?;
let src = load_mcp_with(&cfg, McpLoadOptions {
    on_server: Some(Arc::new(|r| println!("{} -> {}", r.name, r.status.as_str()))),
}).await;
```

### 2. Register tools as they arrive

```rust
use std::sync::Arc;
use toolnexus::mcp::{McpLoadOptions, load_mcp_with, parse_mcp_config_file};
use toolnexus::{ToolkitOptions, create_toolkit};
let tk = create_toolkit(ToolkitOptions::default()).await?;
let live = tk.clone();
let cfg = parse_mcp_config_file("mcp.json")?;
let src = load_mcp_with(&cfg, McpLoadOptions {
    on_server: Some(Arc::new(move |r| { live.register(r.tools); })),
}).await;
```

### 3. Bound the load

```rust
use toolnexus::mcp::{McpLoadOptions, load_mcp_with, parse_mcp_config_file};
let cfg = parse_mcp_config_file("mcp.json")?;
let src = tokio::time::timeout(std::time::Duration::from_secs(10),
    load_mcp_with(&cfg, McpLoadOptions::default())).await?;
```
