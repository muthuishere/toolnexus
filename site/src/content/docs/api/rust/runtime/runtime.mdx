`Runtime::new` builds the substrate `Agent::run` rides on: a handle table rooted at `root()`, the
three backpressure gates (bounded inbox, per-parent concurrency with FIFO slot transfer, a global
turn gate around ONLY the provider call), hierarchical budgets, and one runtime-wide
`ConversationStore` (conversation id = handle id). `Options` takes the model as `http_client` +
`llm` (a real provider) or `in_process` (a host function) — never both. `wake` runs the turn as a
tokio task; call it inside a runtime.

## When to use it

When you need more than one handle alive: fan work out to several children, keep a long-lived
agent between calls, post unsolicited events into its inbox, or drive interrupt/close yourself.
For one agent to completion, `agents::new(..).run(opts, prompt)` already does spawn + wake + wait +
close.

## Example

```rust
use std::sync::Arc;
use toolnexus::agents::{Def, InboxItem, Options, Runtime};
use toolnexus::client::InProcessResponse;

let mut registry = std::collections::HashMap::new();
registry.insert("peer".to_string(), Def { name: "peer".into(), does: "team member".into(), ..Default::default() });
let rt = Runtime::new(Options {
    in_process: Some(Arc::new(|_req| Box::pin(async {
        Ok(InProcessResponse { content: "ok".into(), ..Default::default() })
    }))),
    registry,
    ..Default::default()
});
let h = rt.spawn(&rt.root(), "peer", None)?;
rt.post(&h, InboxItem::new("external", "external", "webhook payload")); // drained at the next wake
rt.wake(&h, "process your inbox");
let r = rt.wait(&h, None).await;          // r.status == "done"
rt.close(&rt.root(), None).await;          // stop-all, leaf-first
```

Runnable: `cargo run --example agents`.
