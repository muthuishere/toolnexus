`TranscriptSearch.transcriptSearchTool` turns a conversation store into a plain, read-only tool named `transcript_search`. The
model calls it with `{query, conversationId?, limit?}`. It does a case-insensitive substring
match over the text of every message: plain content, text parts, tool-call arguments (as JSON)
and tool-result text. Conversations come in the order the store's `list()` returns them (newest
first), and messages in index order.

The output is one line per hit, `<conversationId>#<index> <role>: <snippet>`. The snippet is
centred on the first match, `snippetChars` characters long (characters, not bytes), with `…`
marking cut text. No hits gives `no matches`. Hits past the limit add a final `(+<k> more)`. An
empty query is an error. The tool never writes. Construction fails if the store has no `list()`.

## When to use it

Use it wherever an agent needs to check **what actually happened** rather than what it
remembered: the [dreamer](/api/java/persona/dreamer/) uses it to verify memory, and a persona
can use it to answer "what did I tell you about X last month?".

## Why this and not the alternative

<Aside type="note" title="Why not write it yourself with defineTool?">
You could wrap `store.list()` and `store.get()` yourself. But messages are stored in each
provider's own shape (OpenAI or Anthropic, plain text or multimodal parts, tool calls), so
"what text is in this message" is fiddly. Getting it the same in every language is exactly
the job this library does. This tool does it once, the same way in all eight ports.
</Aside>

It does not exclude anything by default. To hide the current conversation, give it a store
that filters it out.

## Examples

### 1. The smallest useful call — search everything

```java
import io.github.muthuishere.toolnexus.LlmClient;
import io.github.muthuishere.toolnexus.TranscriptSearch;

Tool search = TranscriptSearch.transcriptSearchTool(
    new LlmClient.FileConversationStore(Path.of("data/conversations")));

ToolResult res = search.execute(Map.of("query", "mt. moon"), new ToolContext());
System.out.println(res.output());
// conv-42#3 user: …we finally got through Mt. Moon after the Zubat swarm…
// (or "no matches")
```

### 2. The realistic case — give a persona its own transcript search

```java
var store = new LlmClient.FileConversationStore(Path.of("data/conversations"));

// Let the persona itself look up what was actually said, not just what it remembered.
Agents.Agent ava = Agents.agentFromDir(Path.of("personas/ava"),
    new Agents.AgentSpec().tools(TranscriptSearch.transcriptSearchTool(store)));
```

### 3. The full surface — options and the narrower inputs

```java
Tool search = TranscriptSearch.transcriptSearchTool(store,
    TranscriptSearch.Options.defaults()
        .maxResults(5)        // ceiling for the limit input
        .snippetChars(80)     // code points, not bytes
        .name("past_chats"));

ToolResult res = search.execute(
    Map.of("query", "invoice", "conversationId", "conv-42", "limit", 3), new ToolContext());
System.out.println(res.output());   // at most 3 lines, then "(+<k> more)" if there were more
```

## Options

| Option | Default | What it does |
|---|---|---|
| maxResults | `20` | Most hits per call, and the ceiling for the `limit` input. |
| snippetChars | `200` | Snippet length in characters (code points), not bytes. |
| name | `transcript_search` | The tool name the model sees. |

Input fields the model fills in:

| Field | Type | What it does |
|---|---|---|
| `query` | string | Required, non-empty. Case-insensitive substring. |
| `conversationId` | string | Search only this conversation. |
| `limit` | integer | Fewer hits than `maxResults`. |
