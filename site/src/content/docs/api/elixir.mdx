Package **`toolnexus`** (Hex), Elixir ≥ 1.16 / OTP 26. See the [combined API Reference](/api/) for
every symbol shown in eight-language synced tabs.

<Aside type="note" title="Why the BEAM port exists">
Long-running agents want supervision, isolation, and cheap concurrency — and that is exactly what
**agent orchestration** needs. The Elixir/OTP port is where sub-agents, teams, hierarchical
budgets, and durable suspension feel native (every MCP connection is a supervised process; a
crashed stdio server is isolated as `"failed"` without taking the toolkit down; parallel tool
calls ride `Task.async_stream`). Proving that shape on the BEAM is the reason toolnexus carries
**agentic orchestration across all eight languages** — same contract everywhere, native OTP
underneath. The MCP client is in-house on OTP (no third-party SDK), which is also why this port
ships the **full** elicitation bridge (form *and* URL mode).
</Aside>

## Toolkit

- `Toolnexus.create_toolkit(opts) :: {:ok, toolkit} | {:error, term}` — the aggregator.
  `Toolnexus.create_toolkit!/1` returns the toolkit or raises.
- `opts` (keyword): `:mcp_config`, `:skills_dir`, `:skills`, `:skill_provider`, `:skills_filter`,
  `:skill_sample_limit`, `:builtins`, `:agents`, `:extra_tools`, `:disable_tools`,
  `:disable_skills`, `:wait_for`.
- Equivalents: `createToolkit` (js) · `create_toolkit` (py) · `CreateToolkit` (go) ·
  `Toolkit.create` (java) · `Toolkit.CreateAsync` (c#).

## Skills

- `Toolnexus.Skill.load(input) :: %Toolnexus.Skill.Source{}` — `input` is a path, a list of paths,
  or an options keyword.
- `Toolnexus.Skill.list(input) :: %{skills: [...], skipped: [...]}` — discover + validate; each
  skip is `%{location, reason}` with reasons `missing-name` · `malformed-frontmatter` ·
  `duplicate-name` · `unreadable`.
- A **data skill** is a plain map: `%{name, description, content, resources, base}` (only `:name`
  and `:content` required).
- Equivalents: `loadSkills` / `listSkills` (js) · `load_skills` / `list_skills` (py) ·
  `LoadSkills` / `ListSkills` (go) · `SkillSource.load` / `listSkills` (java) · `SkillSource.Load`
  / `ListSkills` (c#).

## Tools you build — native, HTTP, built-ins

- `Toolnexus.Native.define_tool(name:, description:, input_schema?, execute:)` — `execute` is
  `fn args -> end` or `fn args, ctx -> end`.
- `Toolnexus.Http.tool(name:, description:, method:, url:, headers?, query?, body?, result_mode?,
  timeout?)` — note the function is `tool/1` (not `http_tool`); `:timeout` in ms.
- `:builtins` toggle → ten built-ins: `bash · read · write · edit · grep · glob · webfetch ·
  question · apply_patch · todowrite`. (`Toolnexus.Builtin.tools/0` · `load/1`.)
- Equivalents: `defineTool` / `httpTool` (js) · `define_tool` / `http_tool` (py) · `NativeTool` /
  `HTTPTool` (go) · `NativeTool.of` / `HttpTool.of` (java) · `NativeTool.Of` / `HttpTool.Of` (c#).

## Suspension & the human loop

- `:wait_for` (toolkit option; `fn Request -> Answer`).
- `%Toolnexus.Request{id, kind, prompt, url, data, expires_at}` (serializes `expiresAt`) ·
  `%Toolnexus.Answer{id, ok, data, reason}`.
- `Toolnexus.ToolResult.pending?/1` detects a suspension; a tool suspends by returning
  `%ToolResult{is_error: true, metadata: %{pending: %Request{}}}`.
- Equivalents: `waitFor` / `pending` (js) · `wait_for` / `pending` (py) · `WaitFor` / `Pending`
  (go) · `waitFor` / `ToolResult.pending` (java) · `WithWaitFor` / `ToolResult.Pending` (c#).

## Media generation

Guide: [Media generation](/toolnexus/media/) · recipe: [Generate images, video and speech](/toolnexus/cookbook/media/) · SPEC §7G.

- `Toolnexus.Media.load_style(path) :: {:ok, map()} | {:error, String.t()}`
- `Toolnexus.Media.new(styles, opts \\ [])` — one style map or a list; a verb resolves to the first style
  that declares it. Options: `:on_progress` (`fn %{verb, jobId, status} -> any`, after every poll) ·
  `:transport` (the same injectable seam as `Toolnexus.Client`: `fn request -> {:ok, %{status, headers, body}} | {:error, e}`) ·
  `:http_options` (extra `Req` options, e.g. `plug:` in tests).
- Verbs, each `(media, args, opts \\ [])` with `args` a map or keyword list:
  `image` (`prompt`, `width`, `height`, `aspectRatio`, `seed`) · `video` (`prompt`, `image`, `seconds`,
  `aspectRatio`) · `speech` (`text`, `voice`) · `transcribe` (`audio`) · `clone_voice` (`name`, `samples`) ·
  `talking` (`image`, `audio`). Snake-case atom keys work (`:aspect_ratio`); `:provider_options` in `args`
  overwrites the body last.
- `Toolnexus.Media.generate(media, verb, args, opts \\ []) :: {:ok, Result.t()} | {:error, String.t()}` —
  the raw call; `verb` is a string or atom (`"cloneVoice"`, `:clone_voice`). `opts[:signal]` is cooperative
  cancellation (a pid or zero-arity predicate).
- `%Toolnexus.Media.Result{files: [ContentPart.t()], text, job_id, status}` — files carry `type`,
  `mime_type`, `url`.
- `Toolnexus.Media.tools(media) :: [Tool.t()]` (source `"media"`), or `create_toolkit(media: media)`.
- `RunResult.files` — maps `%{type, mime_type, url, from, call_id}`, in call order; the same parts are on
  each `tool_calls` entry's `parts`.
- Errors: the function face returns `{:error, message}` (exact §7G string) rather than raising; a signalled
  cancel raises `Toolnexus.Media.Cancelled`. Process-idiom cancellation also works: run in a `Task` and
  `Task.shutdown/1` it. A media tool never raises (`is_error: true`).
- Equivalents: `createMedia` (js) · `create_media` (py) · `CreateMedia` (go) · `Media.create` (java) ·
  `Media.Create` (c#) · `toolnexus.media/create-media` (clojure) · `create_media` (rust).
