import { Aside, Tabs, TabItem } from '@astrojs/starlight/components';

Two ways to get *inside* the loop while it runs: **stream** its events for a live UI, and **hook**
every tool call to guard, rewrite, or transform it.

## Streaming the loop

`stream` emits events as they happen: `text` (assistant token deltas), `tool_call`, `tool_result`,
`usage`, `pending` ([a suspension](/toolnexus/suspension/)), and a terminal `done` carrying the final
result. With an `id` it's stateful, exactly like [`ask`](/toolnexus/memory/) — the thread loads
first and saves on `done`.

<Aside type="caution" title="Clojure has no streaming loop">
Six ports ship `stream`. The **Clojure** port does not: its `run` buffers the whole provider
response, so it emits **no `text` deltas** — and synthesising deltas out of a buffered body would
be a lie. Everything else in the event vocabulary (`tool_call`, `tool_result`, `pending`, `usage`,
`done`) is live on the `:on-event` sink shown in its tab, which covers the progress-reporting case.
For character-level output, call the provider's SSE endpoint yourself and use the toolkit only for
the schema. It is tracked as this port's one declared streaming gap.
</Aside>

```ts
for await (const ev of client.stream("Summarize the repo.", { toolkit: tk, id: "user-42" })) {
```

```clojure
;; whole response, and synthesising deltas out of a buffered body would be a lie.

(client/run llm "Summarize the repo."
            {:toolkit         tk
             :conversation-id "user-42"
             :on-event (fn [ev]
                         (case (:type ev)
                           "tool_call"   (println "\n→" (:name ev))
                           "tool_result" (println "  " (:name ev)
                                                  (if (:isError ev) "failed" "ok"))
                           "pending"     (println "waiting on"
                                                  (get-in ev [:request :prompt]))
                           "done"        (println (str "\n(" (:turns (:result ev)) " turns)"))
                           nil))})
```

<Aside type="tip">
Prefer the final result but still want live text? `ask(prompt, { id, on_text })` streams deltas to a
callback while still returning the completed `RunResult` — no need to consume the event iterator
yourself.
</Aside>

## Hooks — guard and transform every tool call

`beforeTool` runs before a tool executes: return an override with **args** to rewrite the call, or
with **result** to *short-circuit* it (deny, cache-hit, dry-run — the real tool never runs).
`afterTool` runs after, and can replace the result (redact, annotate). Here's a policy guard that
blocks a dangerous `bash`:

<Tabs syncKey="lang">
<TabItem label="JavaScript">
```ts
const client = createClient({
  baseUrl, style: "openai", model,
  hooks: {
    beforeTool: ({ name, args }) => {
      if (name === "bash" && /rm -rf/.test(String(args.command)))
        return { result: { output: "denied by policy", isError: true } }   // tool never runs
    },
    afterTool: ({ result }) => ({ result: { ...result, output: redact(result.output) } }),
  },
})
```
</TabItem>
<TabItem label="Python">

```clojure
(def llm
  (client/create-client
    {:base-url base-url :style "openai" :model model
     :hooks {:before-tool (fn [{:keys [name args]}]
                            (when (and (= "bash" name)
                                       (str/includes? (str (:command args)) "rm -rf"))
                              ;; a short-circuit result: the tool never runs
                              {:result {:output "denied by policy" :isError true}}))
             :after-tool  (fn [{:keys [result]}]
                            {:result (update result :output redact)})}}))
```

There are `beforeLLM` / `afterLLM` hooks too — `beforeLLM` can trim or inject history and swap the
tool set before each model call. A `beforeTool` short-circuit that returns a *suspension* is treated
as a guard-raised pending, not an error — the same [suspension](/toolnexus/suspension/) guarantees
apply.
